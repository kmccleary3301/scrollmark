## Performance Budgets

These budgets are the first release targets for the DB-backed table migration:

- 10k records: first visible rows under 1.5s on development hardware.
- 100k records: first visible rows under 2.5s on development hardware.
- Normal table open: no full search-document load.
- Empty-query table open: no full search worker corpus.
- Deep scroll: no table-code main-thread stall above 250ms.
- Normal browsing memory: visible rows plus bounded page cache, not the full result set.
- Export all: streams from a result descriptor and does not call table `loadAll()`.

## Branch Decisions

- The first implementation slice starts with measurement and DB/query foundations, not the virtualizer.
- The existing advanced search engine remains the semantic reference until a persisted search index is explicitly approved.
- Synthetic fixtures are gated behind `localStorage.twe_enable_synthetic_db_tools_v1 = "1"` or `scrollmarkSyntheticDb=1` in the URL so destructive local seeding is not exposed by default.
- Multi-folder no-query bookmark browsing uses a merged DB-backed folder result source. Search plus folder remains on the lazy worker/search-document path until the persisted search index or projected query path is built.
- Source-local checkpoints are the progressive deep-scroll strategy. Capture index pages and folder source index pages are the preferred random-access strategies when a count/revision-matched persisted page map exists; bounded offset fallback remains only for sources without a current index.
